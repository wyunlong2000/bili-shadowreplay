# 自动化切片实施详细设计

> **文档版本**：v1.1 | **最后更新**：2026-10-22 | **状态**：设计评审与完善

## 1. 定位与交付边界

本文把[总体设计](design.md)细化为文件级实施任务、数据契约、UI 规格和联调清单。
内容类型、选片原则与产品范围以总体设计为准，本文负责实现方式和交付依赖。
新增类型、字段、模块和界面均为拟实施内容，代码检查依据为本文所列文件和方法。

**工程红线（既有代码零擅改原则）**：

- 未经用户显式许可，**不得修改任何既有业务代码**；哪怕旧代码存在潜在隐患，
  也只在本设计中记录提醒并在新增模块（如 `automation/`、`database/automation.rs`）
  中通过独立函数旁路规避，禁止顺带修改或重构既有函数实现。
- 涉及现有文件（如 `main.rs`、`recorder_manager.rs` 等）的必要挂载点改动，
  在实际编码前必须先向用户列出改动点并取得明确授权。

交付目标是：选定房间下播后自动分析，按内容类型生成高光，
分别产出原声增强版、AI 解说版及其可编辑工程。
用户已明确需要两种版本，默认输出偏好采用 `Both`。
自动生成文件与自动投稿分别建模，本方案交付前者。

实施拆为 **P1a 原声核心闭环（Timeline V1）**、**P1b 原声增强提示轨（Timeline V2）**、
**P2 解说与增强轨道**、**P3 集成验收**。
P1 同步完成基础 UI 和恢复能力，P2 同步完成新增轨道的编辑与预览。
不把错误展示、取消或恢复推迟为可选收尾工作。

| `recorder_manager.rs` | 整场处理被 `auto_generate.enabled` 控制 | 高光调度独立于整场开关（挂载前需确认） |

| `project.rs::single_full_material` | 仅检查字幕、弹幕和视频裁剪 | 新增轨道启用时（P1b/P2）参与快速导出判断 |
| `project.rs::Timeline::validate` | 主要校验视频片段范围 | 新增轨道启用时校验解说、提示、资源引用与版本 |
| `project-timeline.ts::parseTimeline` | 显式构造已有字段 | 扩展解析，防止保存时丢弃新增轨道 |
| `project-timeline.ts::splitClip` | 只分配视频与字幕 | 提示分配到两侧；解说仅锚定触发起点、持续时间投射到工程全局时间轴（支持 L-cut） |
| `ProjectEditor.svelte` | 浏览器生成 ASS 并传给导出 | 新增后端 `ffmpeg/ass.rs` 编译及双端共享夹具一致性验证 |
| `ffmpeg/project.rs` | 拼接原音频、叠加字幕与弹幕（图片输入索引从 `clips.len()` 起算） | 混音时 `amix` 显式设 `normalize=0`；新增解说音频输入后同步偏移弹幕图片输入索引 |

本节中的 Rust 文件均位于 `src-tauri/src/`；
前端时间轴文件位于 `src/lib/`，编辑器位于 `src/lib/components/project/`。

## 3. 后端模块与依赖

### 3.1 新增模块

在 `src-tauri/src/automation/` 内按职责组织：

| 文件 | 职责与主要入口 |
| --- | --- |
| `mod.rs` | `AutomationService` 生命周期、启动、停止和取消 |
| `types.rs` | 内容类型、输出模式、任务状态、来源与结果 DTO |
| `policy.rs` | 全局配置与房间覆盖合并、校验、策略指纹 |
| `scheduler.rs` | 待执行记录认领、租约、父流程与检查点恢复 |
| `source.rs` | 场次来源清单、封口判断、排序和时间映射 |
| `analysis.rs` | 窗口推进、转写缓存、证据索引和模型分析 |
| `scoring.rs` | 按类型筛选、边界校准、去重与场次复选 |
| `plan.rs` | 原声、解说方案生成及受控操作校验 |
| `render.rs` | 素材与工程创建、提交渲染、结果登记和检查 |

优先使用现有 Rust 依赖。模块划分用于明确职责，不要求每个文件提前建立空壳。
新方法写准确的中文方法注释，异常、单位和副作用在对应方法注释中说明。

### 3.2 运行时注入

`AutomationContext` 只持有数据库、配置、录制管理器、任务队列、事件总线、
资源目录和模型服务引用，不持有完整 `State`。
`State` 增加 `Arc<AutomationService>`，避免形成服务持有 `State` 的引用环。

GUI 与 headless 两条初始化路径都按以下顺序处理：

1. 执行数据库迁移，初始化配置、事件与现有任务队列。
2. 创建共享 `Notify`，注入录制管理器和自动化服务。
3. 完成录播重建及身份、播放列表修复，建立可用来源基础。
4. 对中断的自动化业务记录做恢复判定，随后启动自动化调度。
5. 界面和 HTTP 命令使用同一个服务实例。

调度采用持久化待执行记录、`Notify` 唤醒和低频补扫。
唤醒丢失不应丢任务，内存通知不作为任务的权威状态。
关闭应用时停止认领新任务，取消活动请求和子进程，保存可恢复检查点。

### 3.3 录制生命周期接入

修改 `recorder_manager.rs` 时，把自动化入口放在整场生成开关判断之外。
`LiveEnd` 分别触发高光任务登记和已有整场生成，两者没有执行先后依赖。

高光登记只读取有效房间策略并写入待处理场次，不做转写、模型请求或渲染。
自动触发键由平台、房间和场次构成，重复事件复用同一记录。
策略指纹保存在首次登记的配置快照中，后续配置修改不使重复事件再次生成作品。
来源清单和输入指纹由后台等待录制段封口后计算。

`RecordEnd` 唤醒段落收尾检查；用户停录但场次未结束时，不伪造 `LiveEnd`。
手动分析入口只接受已封口范围，支持单段和整场两种明确范围。
无法确认段落稳定时进入等待状态并展示原因，不读取仍在写入的末段。
封口优先检查播放列表结束标记；缺少标记时，对照录制器确认已停止写入，
并等待连续两次来源指纹一致。重启恢复录制状态前不执行这个兜底判断。

### 3.4 调度、进度和取消

场次协调运行在轻量 Tokio 任务中，ASR、模型请求和渲染分别限流。
FFmpeg 裁剪与渲染使用 `TaskManager`，协调器不占其执行槽。
导出服务已负责入队时，调用者不能再把外层等待流程放进同一队列。

场次父任务使用 `automation_run` 类型。渲染子任务按版本使用
`automation_original`、`automation_commentary`，元数据保存父任务和结果标识。
配音与模型分析的细分阶段保存在结果记录中，避免为每次请求创建任务卡片。

`ProgressReporter` 的可测进度仍使用媒体秒数。
模型阶段显示“已分析窗口数/总窗口数”等文本，不把窗口数当作秒数或编造剩余时间。
候选与双版本进度由业务查询 DTO 返回。

取消按目标分为场次和单个输出。取消场次要先记录取消意图，再取消尚未完成的结果；
单个输出取消不得删除共享素材或另一版本已完成的文件。
`handlers/video.rs::cancel` 根据任务类型分发到自动化服务或现有队列逻辑。

## 4. 配置与模型服务

### 4.1 配置结构

在 `config.rs` 中增加带默认值的 `AutoClippingConfig`，不复用整场生成的布尔开关。
全局配置包括下播自动触发、默认内容类型、自动分类、输出模式、策略版本、
窗口大小、重叠范围、数量上限、输出样式和模型资源限制。

房间覆盖保存在数据库，采用可空字段表示继承；不向录制器的身份或 `extra` 字段塞入策略。
有效配置为“全局默认、房间覆盖、本次显式请求”逐层合并的结果。
任务保存合并后的快照，配置修改不影响进行中的任务。

下播自动触发开关关闭时，用户仍可手动分析已完成录播。
自动分类关闭且类型为 `Mixed` 时，保存设置返回可定位的配置错误。
原声版不要求 TTS 就绪；解说版和双版本请求按实际模型能力检查。

配置写入使用已有 `Config::try_save`，向调用者返回保存失败原因。
保存成功后再发布配置变更，磁盘写入失败时不能展示为已保存。
保存操作在配置写锁下克隆配置、合并并校验修改、持久化，成功后才替换内存配置。
失败时保留原内存值，避免界面显示失败但运行策略已经发生变化。
配置示例同步更新到 `src-tauri/config.example.toml`。

### 4.2 文本和视觉服务

新增 `src-tauri/src/llm/mod.rs` 统一文本和图像请求所需的公共能力。
保留 `agent/mod.rs::llm_prompt` 的调用契约，让它委托公共客户端；
聊天消息与工具确认循环仍归 Agent，自动化提示模板归自动化模块。

公共客户端返回结构化响应、实际用量和明确错误类型，并支持超时与取消。
自动化使用“带来源的文本和图像”输入；原生视频仅为选定服务增加专用适配。
已有 `openai`、`ollama` 提供商枚举和文本可用性不能替代视觉能力检查。

首版只实现用户选定的一种视觉适配，其他服务维持可扩展接口。
模型测试返回文本、视觉、结构输出能力是否可用以及失败原因，凭证不回显。
新增配置必须使用可序列化、可校验的类型，禁止自由透传模型生成的请求参数。

### 4.3 语音合成服务

新增 `src-tauri/src/tts/mod.rs`，定义 `TtsProvider`、生成请求和音频结果。
在 `tts/http.rs` 实现选定服务的 HTTP 适配，保存端点、模型和声音等配置。
具体请求体由所选提供商确定，不能假定所有 TTS 都兼容同一接口。

输出至少包含音频文件、采样信息和实测时长；句级时间来自可靠服务结果或音频对齐。
没有字级时间时使用句级字幕。按文案、声音、参数及模型版本缓存配音。
本地推理可接服务端点，是否随应用分发模型依赖由部署资源决定。

### 4.4 用户输入与自动执行的边界

模型只返回证据引用、候选和受控剪辑操作，不执行聊天工具或任意命令。
字幕、弹幕、OCR 结果均按内容处理，不修改系统策略。
分析预算、输出目录和资源引用由有效配置决定。
模型测试会发起真实请求，应由用户点击测试入口触发，普通设置页加载不自动测试。

## 5. 数据迁移与存储契约

### 5.1 表的调整

检查点中最新迁移编号为 23。P1、P2 分别追加后续迁移，实施时取未占用编号。
自动化表的调整不要求改动录制器主键或重建账号表。

| 表 | 新增或调整内容 | 唯一性 |
| --- | --- | --- |
| `automation_room_policies` | 平台、房间、覆盖配置、修订号和更新时间 | 平台与房间 |
| `automation_runs` | 场次、请求键、配置快照、来源清单、状态和租约 | 请求键 |
| `automation_analysis` | 增加运行标识、来源指纹、证据与阶段检查点 | 运行与录制段 |
| `automation_candidates` | 增加运行标识、类型、证据、评分项和修订号 | 运行、录制段与区间 |
| `automation_outputs` | 具体输出模式、方案、工程、资产、状态与检查结果 | 候选、模式与方案版本 |

分析表的主键与候选表的唯一约束涉及变化，采用事务内重建表、复制数据、建立索引。
无运行标识的数据生成兼容运行记录；迁移后的行数、来源与状态要可核对。
候选唯一键必须包含 `live_id`，同场不同录制段可以拥有相同的相对时间范围。
迁移前后均执行 GUI、headless 和重复启动验证。

### 5.2 关键字段

`automation_runs` 保存以下业务信息：

- `id`、平台、房间、场次、分析范围和 `request_key`。
- `input_hash`、`config_snapshot_json`、模型及模板指纹。
- `status`、`stage`、父任务标识、租约所有者与期限。
- 来源清单、完成窗口数、错误代码、中文错误信息和时间戳。

`automation_analysis` 的检查点保存已完成窗口、转写缓存和证据索引。
窗口状态的提交与检查点推进在一个事务内完成，失败窗口不能被当作已处理跳过。

候选保存 `content_type`、类型来源、置信度、证据引用、分项评分、
来源范围、推荐理由、人工修改标记和修订号。
`Mixed` 只作为房间默认，候选类型必须具体化或回退为 `Other`。

结果保存具体模式 `original` 或 `commentary`，以及 `plan_json`、`plan_hash`、
方案版本、项目标识、素材引用、资产清单、渲染任务、检查结果和错误。
`Both` 不写入结果模式列，两个版本分别认领、完成和重试。

### 5.3 幂等、人工修改与资产归属

自动事件使用确定性的请求键；手动请求带客户端请求标识，网络重试沿用同一标识。
显式重新分析创建新运行记录，保留已有结果；同一来源有活动运行时先返回活动任务。
按场次和分析范围建立活动运行的唯一约束，避免不同请求标识绕过活动任务检查。
缓存由输入、策略和模型指纹决定，不能仅凭房间和时间判断可以复用。

候选修改携带预期修订号，冲突时返回重新加载提示。
修改范围或类型会生成新方案版本，完成的文件和用户修改过的工程不被覆盖。
发布已提交变更事件后再刷新列表，避免界面读到半成品状态。

文件按以下职责归属：

```text
cache/automation/<run_id>/             分析代理、音频与抽帧缓存
output/automation/<output_id>/         配音、方案资产与最终成片
output/projects/<project_id>/          工程自身封面等文件
```

配音通过结果资产 ID 引用，工程依赖结果资产时不能删除该目录。
工程文件与结果目录之间只保存引用，不重复维护可变配音副本。
删除结果需先检查工程与活动任务引用；工程删除后可保留独立成片。
共享素材沿用素材库关系，并补充活动自动化引用检查。

### 5.4 恢复与状态映射

业务记录的权威状态为 `pending`、`processing`、`waiting`、`success`、
`partial_success`、`failed`、`interrupted`、`cancelled`。
阶段描述处理到哪里，状态描述是否可运行，二者分开。

`tasks` 表继续使用其活动与结束状态约定。
双版本部分成功时，父任务结束并通过结果 DTO 展示部分完成，
不能让任务中心把 `partial_success` 当作仍在运行。

`finish_pending_tasks` 执行后，自动化恢复逻辑按业务记录和资产检查点创建恢复任务，
保存新的展示任务标识。有效完成记录不重置，取消记录不自动重启。
认领和续租使用条件更新，失去租约的执行者不能写入完成状态。

## 6. 分析与剪辑方案实现

### 6.1 媒体索引与转写复用（ASR 与 LLM 分窗解耦）

`automation/source.rs` 通过 `database/automation.rs` 按 `(platform, room_id, parent_id)`
精确过滤同场录制段（规避 `database/record.rs` 旧查询缺少 `platform` 过滤的问题），
显式按开始时间与段标识稳定排序。从播放列表得到稳定媒体范围、分片信息及指纹，
毫秒作为自动化内部单位。调用已有秒制视频方法时在边界统一转换，并检查有限数值、范围和舍入。

**ASR 转写与 LLM 语义分析分窗解耦**：

- **ASR 层不按 300s+30s 重叠切分音频**：现有 `ffmpeg/subtitle.rs` 已内置 `silero_vad`
  与 `cut_and_merge(≤30s)` 自然静音切块和 `rolling_context`。若在 ASR 外层再做 30s
  机械音频重叠，会导致边界断句截断以及同一句话在重叠区因微秒级时间差无法被
  `clamp_overlaps` 合并而产生双重字幕。
- 因此，ASR 按录制段（或长静音边界分段）一次性转写并缓存，同时优先只读复用
  `record_summaries` 表中同源录制段已生成的 `subtitle_srt`，为每条语句分配全局稳定的
  证据标识 `cue_id`。
- **LLM 分析层执行 300s 窗口 + 30s 重叠滑窗**：仅在组装模型请求时，按 `[W_start, W_end)`
  及前后重叠上下文提取语句、弹幕密度和抽帧证据提交给模型。

新增 `ffmpeg/frame.rs` 承担面向文件或播放列表的范围抽帧。
缓存引用包含来源和时间，原图与低清代理不混用时间坐标。

### 6.2 策略与证据

类型枚举及序列化值复用总体设计，在 Rust 与 TypeScript 各有明确类型定义。
策略配置保存必需能力、评分项、长度偏好和解说模板，不复制整套工作流。
分类置信度不足进入通用策略，用户锁定的片段类型不被自动覆盖。

每个字幕、帧或连续事件具有稳定证据 ID，模型只引用本窗口及允许上下文中的 ID。
后端由证据定位候选范围，并验证事实描述、片段完整性和资源边界。
不同窗口的重复事件由来源重叠与语义判断共同消除。
场次复选产出质量足够且内容有差异的候选，允许没有候选。

### 6.3 方案结构、关键帧校准与跨镜头编辑规则

`EditPlan` 以整数毫秒保存源引用、剪辑顺序、标题、重点提示、
原声保留区间、解说文案、证据和输出规格。
编译为工程时间轴后，视频与已有字幕字段继续使用秒，避免全量改变编辑器单位。

**流复制关键帧偏移校准（P1a 核心要求）**：

- 素材截取采用快速流复制时，实际素材文件覆盖的录播起点 `actual_start`（记录于
  `videos.source` 的 `MaterialSource`）通常早于请求的 `requested_start`。
- 编译工程时间轴时，必须将 `TimelineClip` 的入点设为
  `clip.start = (requested_start - actual_start).max(0.0)`，出点设为
  `clip.end = clip.start + requested_duration`；
- 锚定在该片段上的所有证据字幕、提示项和解说触发起点，统一按
  `material_time = source_time - actual_start` 换算，确保预览与导出时裁掉多余前导画面并实现音画字精确同步。

P1a 直接产出标准 Timeline V1 工程（含校准后的片段、原声字幕与可用弹幕）；
P1b 提升时间轴版本并定义 `overlays`、`narrations` 的默认空数组，先启用文本提示；
P2 启用解说与局部放大，P1 遇到非空的未支持轨道应阻止编辑保存。
复杂转场、定格与主体跟踪不作为基础交付前置条件。
模型模板只能提出已经实现的操作类型。

解说项包含片段锚点（`clip_id`）、素材内触发起点（`start`）、资产 ID、文案、实测时长与音量策略。
提示项包含片段锚点、素材内起止、类型、内容和归一化位置或放大区域。

**跨镜头解说锚定与编辑规则（支持 L-cut）**：

- **解说触发起点锚定片段，持续时间投射到工程全局时间轴**：解说项通过 `(clip_id, start)`
  定位其在工程时间轴上的触发起点 `project_start = placed.offset + (start - placed.clip.start)`；
  其音频播放与原声压低区间为 `[project_start, min(project_start + duration, timeline_duration)]`，
  允许一段解说自然跨越相邻快切镜头或分割点，不要求 `start + duration <= clip.end`。
- **移动片段**：锚定项随片段移动，重新计算 `project_start` 并检查不同解说项在工程时间轴上是否发生碰撞。
- **裁剪片段**：超出片段可见范围 `[clip.start, clip.end)` 的提示隐藏；当解说的触发起点 `start` 被裁出片段可见范围时标记待修复。
- **分割片段**：提示按 `cut` 分配到两侧；解说项根据其触发起点 `start < cut` 或 `start >= cut` 归属左或右片段，保持完整音频不截断。
- **删除片段**：移除或标记其锚定项，不留下仍可播放的悬空音轨。
- **修改解说文案**：使对应配音失效，仅重做配音和依赖渲染。

解说时长溢出整条工程总时长或与其他解说重叠时，先改写或扩展有依据的上下文，不能自动截断配音；
任何编辑导致两条解说在工程时间轴重叠或超出工程末尾时，阻止导出并定位到对应项。

## 7. 工程与渲染改动

### 7.2 字幕编译与 FFmpeg 混音渲染

新增 `ffmpeg/ass.rs`，在后端把结构化字幕、提示和样式编译为 ASS。
对齐 `src/lib/subtitle-ass.ts` 的坐标（384×288 旧坐标至 1920×1080 换算）、颜色、
`\\\u2060` 控制符转义、样式字段和字体规则。
以 `scripts/tests/subtitle-ass.test.mjs` 抽出的共享样例验证 Rust 与 TS 两端输出一致。
原声字幕、解说字幕和标题使用独立样式行与层级，排版避免互相遮挡。

`ffmpeg/project.rs::ProjectRender` 在 P1b/P2 阶段增加解说输入与画面提示：

- **过滤图编译顺序**：按“视频拼接、画面强调、字幕与弹幕、音频动态闪避与混合、编码”编译。
- **多输入流索引偏移**：目前 `danmu::image_overlay_chain` 以 `job.clips.len()` 作为首个弹幕表情 PNG 的 `-i` 输入索引；新增 $N$ 个解说音频 `-i` 输入后，若解说音频排在图片之前，弹幕图片起始索引必须更新为 `job.clips.len() + narration_inputs.len()`（或固定将解说音频输入排在弹幕图片输入之后），严防流索引错位。
- **原声闪避（Ducking）与 `amix` 混音规范**：现场原声 `[outa]` 按各段解说的工程时间区间 `[s_i, e_i]` 使用 `volume=enable='between(t,s1,e1)+...':volume=0.25` 动态压低音量；各解说音频统一采样率与声道后按 `adelay={start_ms}|{start_ms}` 定位到工程起点；最终执行 `amix` 混合时**必须显式设置 `normalize=0`**（即 `amix=inputs=K:duration=first:dropout_transition=0:normalize=0`），防止 FFmpeg 默认将整体视频音量除以输入路数 $K$。

`Timeline::single_full_material` 在存在解说、提示或其他渲染操作时返回需要渲染。
`render_hash` 纳入新增轨道、有效样式、配音资产内容指纹和输出规格。
文件写入临时路径（`.part.mp4`），检查通过后原子替换并登记最终产物。

`handlers/project.rs` 的导出和工程投稿共用相同轨道编译，
`handlers/upload.rs` 需要验证解说项目不会命中直接上传原素材的路径。
自动化结果生成完成不触发投稿。

## 8. 命令、事件与前端数据

### 8.1 命令层契约

新增 `handlers/automation.rs`，请求与响应类型归自动化模块。
命令接收 `request` 对象，字段使用 camelCase；返回业务 DTO 沿用 snake_case。
HTTP 读取同样的 `{ request: ... }` 外层，避免与 Tauri 参数结构不一致。

以下是新增能力的契约，不重复维护已有命令清单：

| 能力 | 必需输入与返回 | 关键约束 |
| --- | --- | --- |
| 读写全局、房间策略 | 配置、房间键、预期修订号；返回有效配置与修订号 | 能区分继承和显式覆盖 |
| 模型能力测试 | 所选配置；返回能力、耗时和失败原因 | 显式点击触发，凭证不回显 |
| 启动场次或段落分析 | 请求标识、平台、房间、场次或段列表 | 返回运行和父任务，处理在后台继续 |
| 查询运行与候选 | 范围、状态、分页游标；返回摘要与结果状态 | 使用稳定排序，列表不返回完整转写 |
| 查看候选依据 | 候选标识；返回证据与预览范围 | 只读取当前候选需要的来源 |
| 修改候选或解说 | 标识、预期修订号、受控修改项 | 校验边界，更新版本并使依赖项失效 |
| 重试单版本 | 结果标识；返回执行状态 | 复用已完成检查点，不重做另一版本 |
| 取消运行或输出 | 目标标识；返回已记录的状态 | 幂等取消，传播到所属请求和子任务 |

错误分类至少包括配置缺失、能力不支持、来源不可用、版本冲突、预算耗尽、
服务超时、配音失败、渲染失败和用户取消。
返回错误代码及中文消息，UI 据此显示配置入口、重试或重新加载操作。
自动化错误对象包含 `error_code`、`message`、`retryable`。
`invoker.ts` 增加保留这些字段的错误类型，HTTP 与 Tauri 按相同规则转换。
普通字符串错误保持兼容，取消错误的现有文本约定继续满足调用方判断。
不依赖解析中文错误消息来判断是否需要重试。

`main.rs::setup_invoke_handlers` 注册命令，`handlers/mod.rs` 导出模块。
`http_server/api_server.rs` 注册相同功能的适配器和路由。
查询路由可在 readonly 模式使用；变更、测试和重试路由沿用现有非只读分组。
readonly 是 HTTP 操作限制，不代表停止服务端已配置的录制和自动处理任务。
自动化配置查询返回 `can_write`，供只读页面禁用变更操作并说明原因。

声画预览必须与最终渲染的时间映射和音量策略一致。
新增轨道尚未具备完整预览和保存能力的阶段，界面阻止相应编辑和导出。

### 9.7 任务中心

`task-progress.ts` 增加自动化任务名称、摘要与取消判断。
`Task.svelte`、`TaskCenter.svelte` 展示场次及版本，避免显示原始任务类型字符串。
运行记录决定双版本整体状态，任务卡片的结束状态不替代每版结果状态。
提供“查看候选”和“打开工程”入口，定位参数包含运行或项目标识。
`stores/tasks.ts` 继续使用后端快照和既有事件，页面切换不能自行结束任务。

## 12. 实施依赖与验收任务

### 12.1 开发顺序

1. 固化 DTO、类型、配置和来源坐标，完成数据迁移与存储操作（`database/automation.rs` 独立实现平台级查询）。
2. 接通启动注入、手动任务、下播触发、认领、取消和恢复，使用模拟模型验证。
3. 实现 ASR/LLM 分窗解耦转写、证据索引、类型策略与场次复选，生成可解释候选。
4. 完成后端 `ffmpeg/ass.rs` 字幕编译、关键帧偏移校准（`TimelineClip.start`）、Timeline V1 工程创建与原声导出。
5. 同步交付设置、房间覆盖、录播触发、候选工作区与任务状态（完成 **P1a**）。
6. 扩展 Timeline V2 `overlays` 标题提示轨及编辑器预览保存支持（完成 **P1b**）。
7. 接入选定 TTS，完成跨镜头 `narrations` 解说轨道、`amix(normalize=0)` 混音闪避、预览与文案修改后的增量重做（完成 **P2**）。
8. 使用用户样本调校类型策略，完成双端、故障和资源验收（完成 **P3**）。

步骤 1 至 5 构成 P1a，步骤 6 构成 P1b，步骤 7 构成 P2，步骤 8 构成 P3。
各阶段在功能进入可用状态前完成对应恢复和回归检查，涉及修改既有文件前均须先经用户确认。

### 12.2 自动化与媒体验证

| 验证归属 | 必须覆盖的场景 |
| --- | --- |
| 数据库测试 | 基础表迁移、重复启动、主键变化、同场同时间不同段、认领竞争、跨平台同房间号隔离 |
| 调度测试 | 重复事件与配置变更、单执行槽、源段未封口、取消和租约失效 |
| 模型适配测试 | 无效 JSON、未知证据、超时、预算、能力不足和取消 |
| 时间轴测试 | 关键帧前导偏移校准、版本升级、未知版本保护、跨镜头解说分割与远程合并 |
| 字幕共享夹具 | 样式坐标、颜色、中文、换行和 ASS 控制字符转义（Rust 与 TS 共享用例） |
| 媒体集成测试 | 两段画面、原声与解说混音（`normalize=0` 音量保持）、标题、弹幕图片输入索引偏移及输出时长 |
| 恢复测试 | 配音后重启、渲染中断、文件完成未登记、单版本失败 |
| UI 验证 | 配置继承、范围明确、空状态、部分完成、并发编辑和不可用能力 |

Rust 测试靠近对应模块，前端纯逻辑测试扩展 `scripts/tests/` 的既有方式。
新增自动化、轨道与音频控制测试文件，复用时间轴、任务和状态刷新测试。
ASR、视觉和 TTS 使用固定响应或模拟服务，不让 CI 依赖真实账号和付费请求。

回归至少包含 `yarn check`、`yarn test`、前端构建、文档构建、
GUI 与 headless 编译检查，以及与改动相关的 Rust 测试和仓库必需检查。
界面使用真实浏览器验证拖动、暂停、跳转、静音、窄窗口和错误恢复。
无界面生成需在不打开编辑器的情况下完成一条原声和一条解说视频。

### 12.3 阶段完成定义

P1a 完成：不改动现有编辑器轨道，同场录播能够自动生成经关键帧校准、有来源依据的原声切片与 V1 工程，
用户可查看候选、修改类型和边界、打开工程，重启与取消不产生重复或损坏文件。

P1b 完成：支持 Timeline V2 `overlays` 标题与重点文字提示轨，编辑器可预览与保存。

P2 完成：同一候选生成两种独立结果，跨镜头解说可编辑、试听并与导出一致；
解说失败不破坏原声版，重试不重新转写和重新生成已完成版本。

P3 完成：各主要内容类型达到约定的人工采用标准，
记录实际耗时和模型消耗，所有必须修复的时间、事实、文件与恢复问题通过验证。
